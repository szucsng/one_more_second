# Android Build Guide

The project ships a configured **Android** export preset, portrait orientation,
immersive mode, adaptive icons and version metadata.

> **Verification status:** the preset was parsed by Godot 4.7.2, but no APK/AAB was
> compiled in this repository because the build environment has no Android SDK/JDK.
> Follow this guide and test on a physical device before release. Do not treat an
> unsigned build as store-ready.

---

## 1. Prerequisites

| Tool | Version |
| --- | --- |
| Godot | 4.7.2 standard, matching Android export template |
| JDK | 17 (Android Gradle Plugin requirement) |
| Android SDK | command-line tools + platform 35 + build-tools 34/35 |
| adb | platform-tools |
| Gradle | bundled by Godot's Android build template for AAB builds |

### Godot editor settings

*Editor → Editor Settings → Export → Android*:

- **Android SDK Path** → e.g. `~/Library/Android/sdk`
- **Debug Keystore** → `~/.android/debug.keystore`
- **Debug Keystore User** → `androiddebugkey`
- **Debug Keystore Pass** → `android`
- **Java SDK Path** (some Godot versions) → your JDK 17 home

Install SDK packages with the command-line tools:

```bash
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
```

Accept licenses:

```bash
sdkmanager --licenses
```

Create a debug keystore if missing:

```bash
keytool -genkey -v -keystore ~/.android/debug.keystore \
  -storepass android -alias androiddebugkey -keypass android \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Android Debug,O=Android,C=US"
```

`adb devices` should list a physical device with USB debugging enabled, or start an
emulator.

## 2. Project settings already configured

In `project.godot`:

- `display/window/handheld/orientation = 1` → **portrait**
- viewport 1080×1920, canvas_items stretch, keep aspect
- Compatibility renderer for broad device support
- `application/config/quit_on_go_back = false` → in-game back handling
- app name: `ONE MORE SECOND`
- version: `1.0.0`

In `export_presets.cfg` (Android preset):

- package/unique name: `com.onemoresecond.game` **← change to your owned domain**
- version code `1`, version name `1.0.0`
- immersive mode enabled
- arm64-v8a enabled; 32-bit/x86 disabled for a smaller store build
  - enable `armeabi-v7a` only if you really need older 32-bit devices;
  - enable x86_64 only for emulator/Chromebook testing.
- adaptive foreground/background/monochrome icons + legacy 192 px icon
- screen support: small/normal/large/xlarge
- user data backup allowed
- Gradle build off (APK by default)

Before publishing, decide on 32-bit support based on your analytics and store
requirements. Google Play requires 64-bit support; arm64-only is valid.

## 3. Debug APK

### Editor

1. *Project → Export…*.
2. Select **Android**.
3. Ensure *Export Path* is `exports/android/one-more-second.apk`.
4. Click **Export Project** (or **Export PCK/ZIP** only if you know why).
5. Install:

```bash
adb install -r exports/android/one-more-second.apk
adb shell am start -n com.onemoresecond.game/com.godot.game.GodotApp
```

The activity name is generated by Godot; use the launcher icon if the explicit
activity differs.

### CLI

```bash
mkdir -p exports/android
godot --headless --path . --export-debug "Android" \
  "$PWD/exports/android/one-more-second-debug.apk"
```

If the export fails, the error usually names the missing SDK component or keystore.
See [troubleshooting.md](troubleshooting.md).

## 4. Release signing

Create a release keystore **outside the repository**:

```bash
keytool -genkey -v -keystore ~/keystores/one-more-second-release.keystore \
  -alias onemoresecond -keyalg RSA -keysize 2048 -validity 10000
```

Enter the passwords interactively. Then in *Editor Settings → Export → Android* set:

- Release Keystore path
- Release User = alias
- Release Password

Do not commit the keystore, passwords or `export_credentials.cfg`. Add them to your
password manager and store an offline backup: losing the upload key can block app
updates.

Release export:

```bash
godot --headless --path . --export-release "Android" \
  "$PWD/exports/android/one-more-second.apk"
```

Verify the signature:

```bash
$ANDROID_HOME/build-tools/35.0.0/apksigner verify --print-certs \
  exports/android/one-more-second.apk
```

## 5. AAB for Google Play

Google Play requires an Android App Bundle (`.aab`).

1. *Project → Install Android Build Template…* (creates an `android/` directory).
2. In the Android preset:
   - enable **Gradle Build**;
   - **Export Format**: **AAB**.
3. Configure the release keystore as above.
4. Export:

   Editor: *Project → Export… → Export Project* to
   `exports/android/one-more-second.aab`.

   CLI:

   ```bash
   godot --headless --path . --export-release "Android" \
     "$PWD/exports/android/one-more-second.aab"
   ```

5. Upload the `.aab` in Play Console → *Production → Create new release*.

The first Play upload may require enabling Play App Signing. Google manages the app
signing key; your local keystore becomes the upload key. Follow Play Console's
current instructions.

### Version codes

`export_presets.cfg` → Android `version/code` must increase for **every** store
upload. `version/name` is the player-visible version. Update both, plus
`project.godot` and `GameConfig.VERSION`.

## 6. Test matrix on Android

Test at minimum:

- [ ] Fresh install, first launch, splash/loading.
- [ ] Portrait lock; no rotation glitch.
- [ ] Touch switches lanes only on the playfield; buttons do not switch lanes.
- [ ] Pause button; Android back pauses/resumes; back from menu exits.
- [ ] Auto-pause on backgrounding (home screen) and resume.
- [ ] Collision, game over, restart, menu.
- [ ] Best score and stats survive force-stop + relaunch.
- [ ] Skin selection persists.
- [ ] SFX/music toggles and volume.
- [ ] Vibration on/off.
- [ ] Reduced effects mode.
- [ ] Safe area/notch: headers and pause button visible on a notched device.
- [ ] 60 FPS-ish on low-end hardware; no thermal runaway.
- [ ] Offline launch and play (ads/store are not required).
- [ ] Test rewarded ad only when a real provider is integrated; v1 is simulated or
      disabled on web.
- [ ] App icon/adaptive icon on the launcher.
- [ ] Play Store internal testing install.

The game does not require internet. v1 has no real ads or purchases, so airplane mode
must be fully playable.

## 7. Store listing assets

- App name: **ONE MORE SECOND**
- Package id: change `com.onemoresecond.game` to your own domain-based id **before
  the first upload**; changing it later creates a new app.
- Icon: 512×512 (`assets/icons/android/play_store_512.png`).
- Adaptive icons: generated in `assets/icons/android/`.
- Feature graphic: 1024×500 (not included; create from brand art).
- Phone screenshots: at least 2; use 1080×1920 captures (the visual harness output is
  a good start, but for store screenshots use gameplay without debug score values).
- Short/full description, support email, privacy policy URL.
- Category: Games → Arcade (or Action/Arcade depending on store taxonomy).
- Content rating questionnaire: no violence, no user-generated content, no data
  collection in v1.
- Data safety form: local saves only; no collection/sharing in v1. Update if ads,
  analytics or IAP are enabled.

Do not claim “no ads” in the store listing if a real ad provider is later integrated
without changing the listing.

## 8. Adding real ads and purchases

Current state: test-only rewarded overlay; store inactive. To ship real monetization:

1. Integrate an AdMob plugin compatible with **Godot 4.7** (for example the Poing
   Studios AdMob plugin, or a maintained fork).
2. Implement an `AdProvider` adapter and wire it in `AdsManager`.
3. Replace the Google **test IDs** in `systems/ads/ad_config.gd` with production IDs
   supplied by the owner; set `AdConfig.TEST_MODE = false`.
4. Add consent (Google UMP / GDPR) and, if personalized ads are used, iOS ATT and
   Android advertising ID disclosures.
5. Configure the Android app ID meta-data required by the plugin.
6. Test on real devices with test ads before enabling paid traffic.
7. For IAP, integrate Google Play Billing, implement `Monetization.store_available`
   and `purchase()`, validate purchases server-side where possible, and grant skins /
   remove-ads only after a verified transaction.

See [monetization.md](monetization.md) for the exact rules and abstraction contract.

## 9. Performance guidance

- The default build is arm64-only, which is appropriate for modern Play devices.
- Compatibility renderer is already selected.
- Reduce Effects lowers particles, glow and shake.
- Profile on a low-end 720p/60Hz device with *Monitors* and *Profiler*; do not infer
  performance from a desktop or flagship phone.
- If you need a smaller APK, use an AAB (Play delivers per-architecture splits) and
  keep only arm64-v8a.
- Avoid adding per-frame node creation; the current spawner and FX are pooled/capped.

## 10. Common Android failures

| Symptom | Fix |
| --- | --- |
| “Android SDK path is invalid” | Install platform-tools + build-tools; set Editor Settings |
| “Java SDK path required” | Install JDK 17 and point Godot to it |
| `apksigner not found` | Install build-tools; set SDK path correctly |
| Export succeeds but install fails | Uninstall old signature; `adb install -r` |
| Release build unsigned | Configure release keystore in Editor Settings |
| AAB export disabled | Install Android build template + enable Gradle Build |
| Game starts in landscape | Check `display/window/handheld/orientation` and manifest |
| Notch overlaps HUD | Verify safe-area code; test on the device, not the editor |
| Haptics missing | Device/permission support; check the VIBRATION setting |
| Store rejects version | Increase `version/code` |
